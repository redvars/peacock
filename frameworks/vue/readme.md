# @redvars/peacock-vue

Vue components for [Peacock](https://peacock.redvars.com), generated from its custom elements manifest. Works with Vue 3.3 and later.

```bash
npm install @redvars/peacock @redvars/peacock-vue
```

```vue
<script setup lang="ts">
import { ref } from 'vue';
import '@redvars/peacock/styles.css';
import { WcInput, WcSwitch } from '@redvars/peacock-vue';

const name = ref('Ada');
const enabled = ref(false);
</script>

<template>
  <WcInput label="Name" v-model="name" />
  <WcSwitch label="Enabled" v-model="enabled" @change="e => console.log(e)" />
</template>
```

- **Names:** `wc-date-picker` is `WcDatePicker`.
- **Props** are set as element properties, so `:options="[...]"` passes the array itself. No `isCustomElement` compiler setting is needed.
- **v-model** binds `value` on fields and `checked` on switches, checkboxes and radios.
- **Events** are emitted with their typed `detail`: `@change`, `@menu-item-activate` and so on.
- **Global registration:** `app.use(PeacockVue)` registers every component and types them in templates (Volar). Importing components where you use them keeps the bundle to what you need.
- **Registration:** importing a component defines its element and the Peacock elements it renders. You don't need `loader.js`.

Full guide: [peacock.redvars.com/frameworks/vue](https://peacock.redvars.com/frameworks/vue/).

## Development

`src/generated/` is generated by `components/bin/framework-gen.mjs`; don't edit it. `npm run build` regenerates it from `../../components/dist/custom-elements.json` (build `components` first) and compiles to `dist/`. `npm run demo` starts the demo in `demo/`.
