# @redvars/peacock-angular

Angular components and form bindings for [Peacock](https://peacock.redvars.com), generated from its custom elements manifest. Works with Angular 17 and later.

```bash
npm install @redvars/peacock @redvars/peacock-angular
```

Add `"@redvars/peacock/styles.css"` to `styles` in `angular.json`, then:

```ts
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { PEACOCK_COMPONENTS } from '@redvars/peacock-angular';

@Component({
  selector: 'app-example',
  imports: [FormsModule, ...PEACOCK_COMPONENTS],
  template: `
    <wc-input label="Name" [(ngModel)]="name"></wc-input>
    <wc-select label="Choice" [options]="options" [(ngModel)]="choice"
               (change)="log($event.detail.value)"></wc-select>
  `,
})
export class Example {
  name = 'Ada';
  choice = 'alpha';
  options = [{ label: 'Alpha', value: 'alpha' }, { label: 'Beta', value: 'beta' }];
  log(value: string) { console.log(value); }
}
```

- **Components:** one standalone component per element (`WcButton`, `WcInput`, …). You write the tags as they are, with no `CUSTOM_ELEMENTS_SCHEMA`.
- **Strict templates:** inputs and `$event` are typed, `(change)` included.
- **Forms:** `ngModel`, `formControl` and `formControlName` work on every field and toggle, including disabled state and touched on blur. `PEACOCK_COMPONENTS` includes the value accessors; if you import single components, add `PEACOCK_VALUE_ACCESSORS`.
- **Registration:** the package defines the Peacock elements itself, so you don't need `loader.js`.

Full guide: [peacock.redvars.com/frameworks/angular](https://peacock.redvars.com/frameworks/angular/).

## Development

`src/generated/` is generated by `components/bin/framework-gen.mjs`; don't edit it. `npm run build` regenerates it from `../../components/dist/custom-elements.json` (build `components` first) and packages it with ng-packagr into `dist/`. `npm run demo` serves the demo in `demo/`.
